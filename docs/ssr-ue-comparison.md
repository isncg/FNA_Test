# SSR 实现对比：SceneRenderer vs Unreal Engine

> 生成时间：2026-08-01
> 对比基准：UE4 `ScreenSpaceReflections.usf` / `ScreenSpaceRayCast.usf` /
> `ReflectionEnvironmentShaders.usf`（Epic Games, Inc.）
> 我们的实现：`SceneRenderer/Shaders/SSR_ps.hlsl` + `DeferredLighting_ps.hlsl`

---

## 背景：什么是 SSR

屏幕空间反射（Screen-Space Reflections, SSR）是一种在延迟渲染管线中生成
实时反射的技术。它的基本思路是：对于每个需要反射的像素（如光滑地板），沿
反射方向发射一条光线，在**当前屏幕已渲染的深度缓冲**中逐步前进（ray
march），寻找光线与场景表面的交点，然后在该交点处读取颜色作为反射内容。

SSR 的优势是它能反射**任何屏幕中可见的几何体**（包括动态物体），而不需要
预先烘焙环境贴图。它的局限是只能反射屏幕内的内容——光线射出屏幕边界或
未命中任何表面时，需要回退到环境贴图（IBL）等替代方案。

UE 的 SSR 是业界最成熟的实现之一。下面按子系统逐项对比。

---

## 1. 光线行进与命中检测

### 1.1 问题背景

ray march 的核心决策是：**如何判断光线已经"打中"了一个表面？**

深度缓冲存储的是从相机看到的每个像素的距离。光线在屏幕空间中逐步前进时，
每一步都有一个"光线深度"（光线当前位置到相机的距离）和一个"场景深度"
（该屏幕位置已渲染的最近表面到相机的距离）。两者的差值
`depthDiff = 光线深度 - 场景深度` 决定了命中判定策略。

### 1.2 UE 的做法：厚度窗口（Thickness Window）

```
Hit = abs(depthDiff + CompareTolerance) < CompareTolerance
```

等价于 `-2 × Tol < depthDiff < 0`：光线必须刚好在表面**后方**一个很薄的
"厚度窗口"内才算命中。`CompareTolerance` 是自适应的，正比于光线每步的
深度变化量（`abs(RayStepUVz.z) * Step`），步长越大窗口越宽。

命中后用**线段插值**（一步）细化交点：

```
TimeLerp = saturate(DepthDiff_prev / (DepthDiff_prev - DepthDiff_curr))
```

### 1.3 我们的做法：符号穿越（Sign Crossing）+ 二分搜索

```
Hit = (prevDiff <= 0) && (depthDiff > 0.001)
```

检测 `depthDiff` 从 ≤0（光线在表面前方）变为 >0（光线在表面后方）的瞬间。
命中后用 **5 次二分搜索**精确收敛到交点。

### 1.4 视觉差异

| 场景 | UE（厚度窗口） | 我们（穿越检测） |
|------|--------------|----------------|
| 光滑地板反射茶壶 | 只检测到茶壶**顶面**附近（depthDiff 在窗口内），倒影整体偏移一个壶身高度 | 正确检测到茶壶**底面**（首次穿越），倒影位置准确 |
| 不同高度的物体 | 各物体偏移量不同 → **分层**（layering）：高物体倒影偏移大，矮物体偏移小 | 所有物体在首次穿越处一致检测 → 无分层 |
| 物体轮廓边缘 | 光线一步跨越整个深度不连续（depthDiff 远超窗口）→ **自动拒绝** | 穿越检测也会触发 → 需要额外的边缘衰减（见 §3） |
| 薄物体（如栏杆） | 光线可能一步跳过整个物体（depthDiff 先正后负，但正值超出窗口）→ 漏检 | 穿越检测能捕获 → 更完整 |

**总结**：穿越检测在几何准确性上优于厚度窗口（正确捕获底面、无分层、不漏
薄物体），但在轮廓边缘更敏感，需要额外补偿。

### 1.5 性能差异

| | UE | 我们 |
|---|---|---|
| 粗步进 | 8–16 步（向量化 4 路，HZB 加速） | 64 步（标量逐步） |
| 细化 | 线段插值（0 次额外采样） | 5 次二分搜索（5 次额外深度采样） |
| 每像素最大深度采样 | ~16 次 | 64 + 5 = **69 次** |

UE 的 HZB（Hierarchical-Z Buffer，见 §2）允许光线在空旷区域大步跳跃，
只在接近表面时细化，实际平均步数远少于 NumSteps。我们的等步长线性行进
没有这种加速，每像素固定 64 步。

## 2. 深度缓冲加速结构

### 2.1 问题背景

ray march 的主要开销是**深度采样**：每一步都要在深度缓冲上采样一次来比较
深度。如果光线穿过一大片空旷区域（如从地板射向远处的墙壁），等步长行进
会浪费大量步骤在"什么都没有"的空间上。

### 2.2 UE 的做法：HZB（Hierarchical-Z Buffer）

UE 维护一个深度缓冲的 **mipmap 金字塔**（HZB）：每一级 mip 存储 2×2 区域
的最大深度（即最远距离）。光线行进时：

- 在**高 mip**（低分辨率）上大步前进：每步覆盖多个像素，快速穿越空旷区域
- 当高 mip 的深度表明光线可能接近表面时，**降低 mip**（提高分辨率）细化
- 粗糙表面使用更高的起始 mip（`Level = Roughness * ...`），既加速又隐式
  模糊了反射

这相当于一个**层次化搜索**：先粗后细，类似 BVH 在光线追踪中的作用。

### 2.3 我们的做法

无 HZB。等步长线性行进（`stepSize = 0.5` 世界单位），每步在全分辨率
GBuffer 深度上采样。

### 2.4 影响

| | UE（HZB） | 我们（线性） |
|---|---|---|
| 远距反射 | 高效：大步跨越空旷区域 | 低效：64 步可能不够到达远处物体 |
| 近距反射 | 与线性相当 | 正常 |
| 粗糙度模糊 | 隐式：高 mip = 模糊深度 = 模糊命中 | 需要显式 blur（见 §4） |
| 实现复杂度 | 高：需要额外的 HZB 生成 pass + mip 管理 | 低 |

## 3. 轮廓边缘处理

### 3.1 问题背景

当反射光线恰好从物体轮廓（silhouette）旁边经过时，深度缓冲在该处有一个
**阶跃**（从物体前表面深度突然跳到背景深度）。命中检测可能在这个阶跃处
误触发，产生一圈明亮的"轮廓光"（edge glow）——在 SSR 调试视图中表现为
物体边缘的亮线，在最终画面中表现为错误的亮边反射。

### 3.2 UE 的做法：隐式拒绝

UE 的厚度窗口天然解决了这个问题：在轮廓处，光线一步跨越整个深度阶跃，
`depthDiff` 远大于 `CompareTolerance` → 不满足 `abs(depthDiff + Tol) < Tol`
→ 自动判定为未命中。不需要任何额外的边缘检测逻辑。

### 3.3 我们的做法：显式边缘衰减

穿越检测对任何符号变化都敏感，在轮廓处也会触发。我们用两个机制补偿：

**a) 深度感知模糊的权重缩放（`weightSum / 9`）**

history 采样的 3×3 模糊核中，每个 tap 与命中点做深度比较；深度差异过大
的 tap 被排除。`coverage *= weightSum / 9`：如果大部分 tap 被排除（命中
在深度不连续处），coverage 降低 → 回退到环境反射。

**b) 固定半径轮廓检测（`edgeMask`）**

在命中点周围 3 像素半径处采样 4 个方向的深度。若任一方向深度突变超过
阈值（10% 相对深度），命中在轮廓线上 → `coverage *= 0`。

### 3.4 对比

| | UE | 我们 |
|---|---|---|
| 机制 | 厚度窗口隐式拒绝 | 显式 edgeMask + weightSum |
| 额外开销 | 无 | 4 次深度采样（edgeMask）+ 9 次深度采样（blur 权重） |
| 效果 | 轮廓处完全无 SSR（可能过于保守） | 轮廓处 coverage 归零，内部正常 |

## 4. 粗糙度模糊

### 4.1 问题背景

真实世界中，粗糙表面的反射是**模糊**的：微观法线方向分散，反射光覆盖一个
锥形区域（GGX lobe），而非单条光线。SSR 需要模拟这种模糊——否则粗糙表面
的反射会和光滑表面一样锐利，不符合物理。

### 4.2 UE 的做法：HZB Mip + 多射线

UE 的粗糙度模糊有两个层次：

- **HZB mip 级别**：`Level = Roughness * (i * 4.0 / NumSteps) + offset`。
  粗糙表面在更低的分辨率（更高 mip）上采样深度和颜色，硬件 mipmap 过滤
  自动产生模糊。这既是加速手段也是模糊手段。
- **多射线锥追踪**（高质量级别）：`NumRays = 4–12`，用 GGX 重要性采样
  生成多条反射光线，每条独立行进，结果平均。这是物理上最准确的方式，
  但开销成倍增长。

### 4.3 我们的做法：3×3 深度感知 Bilateral 核

单射线行进，命中后在 history 缓冲上做 3×3 模糊：

```
blurRadius = roughness * 2.0  // 模糊半径正比于粗糙度
每个 tap：
  if |tapDepth - hitDepth| < threshold → 纳入平均
  else → 排除（防止跨深度不连续渗色）
```

这是一个**双边滤波**（bilateral filter）：空间上邻近且深度相似的 tap 参与
平均，深度不同的 tap（如物体轮廓另一侧）被排除。

### 4.4 对比

| | UE | 我们 |
|---|---|---|
| 模糊质量 | 高：mip 过滤 + 多射线 GGX 锥 | 中：3×3 固定核，粗糙度仅控制半径 |
| 深度感知 | 隐式（mip 平均化边缘） | 显式（逐 tap 深度比较） |
| 每像素开销 | 1×（单射线）到 12×（多射线） | 1× + 9 次 history 采样 + 9 次深度采样 |
| 各向异性 | GGX 采样天然各向异性 | 各向同性（圆形核） |

## 5. History 缓冲与时域采样

### 5.1 问题背景

SSR 行进发生在延迟光照**之前**（因为 SSR 结果要被光照 pass 消费），所以
当前帧的完整光照颜色还不存在。命中点需要读取"那个位置看起来是什么颜色"，
这通常通过采样**上一帧**的完整渲染结果（history buffer）来实现。

### 5.2 UE 的做法

UE 采样上一帧的 **SceneColor**（`PREV_FRAME_COLOR`），包含完整的光照 +
天空盒 + 后处理。命中点通过 `ClipToPrevClip` 矩阵重投影到上一帧的屏幕
坐标。屏幕边缘用 **Vignette** 平滑淡出：

```
Vignette = saturate(abs(HitScreenPos) * 5 - 4)
OutColor *= 1 - dot(Vignette, Vignette)
```

UE 没有多帧时域累积（在 SSR pass 本身中），但依赖 TAA/TSR 在后续 pass
中提供时域稳定性。

### 5.3 我们的做法

采样上一帧的 **HdrSceneRT**，但**排除天空盒**：`UpdateHistory` 在
DeferredLighting 之后、Skybox 之前执行。环境/天空反射由光照 pass 的
IBL 项单独提供（通过合成公式 `SSR.rgb + EnvSpecular * (1 - SSR.a)`）。

屏幕边缘处理：`prevUV` 越界时硬切到 GBuffer albedo 回退，无渐变 Vignette。

### 5.4 对比

| | UE | 我们 |
|---|---|---|
| History 内容 | 完整 SceneColor（含天空） | 仅几何体光照（无天空） |
| 天空反射来源 | History 中的天空 + 反射探针 | IBL 项（prefiltered envmap）独立提供 |
| 边缘淡出 | Vignette 平滑渐变 | 硬切到 albedo |
| 重投影 | `ClipToPrevClip`（单矩阵） | 世界空间中转（invView → PrevViewProj） |
| 时域累积 | 依赖 TAA/TSR | 无（单帧 history） |

**视觉影响**：

- 我们的 history 不含天空 → SSR 反射中不会出现天空盒渗透（UE 中天空盒
  反射由 SSR 和反射探针共同提供，可能在轮廓处混合出天空色）。
- 我们缺少 Vignette → 反射在屏幕边缘可能突然截断（UE 平滑淡出）。
- 我们缺少时域累积 → 反射可能有单帧闪烁（UE 通过 TAA 稳定）。

## 6. 合成管线

### 6.1 问题背景

SSR 只能反射屏幕内的内容。当 SSR 未命中（光线射出屏幕或未碰到表面）时，
需要回退到**环境反射**（IBL：Image-Based Lighting，通常来自预过滤环境
贴图）。合成策略决定了 SSR 命中与未命中之间的过渡是否自然。

### 6.2 两者的做法（一致）

UE 和我们都使用**预乘 alpha over 合成**：

```
FinalSpecular = SSR.rgb + EnvSpecular × (1 - SSR.a)
FinalSpecular *= SpecularColor   // Fresnel + split-sum (EnvBRDF)
```

- SSR 命中（`a → 1`）：环境反射被遮蔽，只显示 SSR 内容
- SSR 未命中（`a = 0`）：完全回退到环境反射
- 中间状态：按 coverage 混合

SpecularColor（Fresnel + split-sum 近似）在合成**之后**统一乘到两个来源
上，确保表面反射率一致地影响两者。

高光遮蔽（Specular Occlusion）也一致：

```
SpecularOcclusion = saturate((NoV + AO)² - 1 + AO)
SpecularColor *= SpecularOcclusion
```

Off-specular peak 修正也一致（环境查找方向偏向法线），但 UE 不做
normalize（cubemap 采样不需要单位向量），我们因为等距柱状投影查找
（`asin(dir.y)`）需要单位向量而额外 normalize。

## 7. Stencil 遮罩

### 7.1 问题背景

不是所有表面都需要 SSR（如粗糙墙壁）。跳过这些像素可以节省大量开销。

### 7.2 对比

| | UE | 我们 |
|---|---|---|
| 机制 | `r.SSR.Stencil`：独立 stencil prepass，不需要 SSR 的像素 `discard` | GBuffer pass 写 stencil 标记，SSR pass 测试 `Equal 1` |
| 粒度 | 基于粗糙度 + ShadingModel（自动） | 基于 per-object `ReceivesSSR` 标志（手动） |
| 非接收器处理 | prepass 写 `OutColor = 0`，保留 stencil | 写 stencil = 0（`DepthWriteStencilClear`） |

UE 的方式更自动化（粗糙度超阈值自动跳过），我们的方式更手动但更灵活
（可以按物体控制）。

## 8. 性能总结

以单像素、最大质量路径为基准的**每像素深度/颜色采样次数**估算：

| 阶段 | UE（Quality 2, 单射线） | UE（Quality 4, 12 射线） | 我们 |
|------|----------------------|------------------------|------|
| 粗步进深度采样 | ~16（HZB 加速，实际更少） | ~16 × 12 = 192 | 64 |
| 细化 | 0（线段插值） | 0 | 5（二分搜索） |
| 边缘检测 | 0 | 0 | 4（edgeMask） |
| 颜色采样 | 1 | 12 | 9（3×3 blur） |
| 模糊深度采样 | 0（mip 隐式） | 0 | 9（bilateral 权重） |
| **合计深度采样** | **~16** | **~192** | **82** |
| **合计颜色采样** | **1** | **12** | **9** |

关键差异：

- UE 的 HZB 使实际步数远低于 NumSteps（空旷区域一步跨越数十像素），
  我们的等步长每像素固定 64 步，**远距反射效率差距最大**。
- UE 的细化零开销（线段插值），我们的二分搜索额外 5 次采样。
- 我们的边缘检测和 bilateral 模糊增加了 ~22 次额外采样，这是穿越检测
  方案的必要代价。
- UE 的多射线路径（Quality 3–4）开销成倍增长但质量最高；我们没有
  多射线支持。

## 9. 视觉质量总结

| 方面 | UE | 我们 | 评价 |
|------|---|---|------|
| 倒影几何准确性 | 厚度窗口可能分层 | 穿越检测无分层 | **我们更好** |
| 轮廓边缘干净度 | 厚度窗口隐式拒绝 | 显式 edgeMask | 等价 |
| 粗糙表面模糊 | HZB mip + GGX 多射线 | 3×3 bilateral | UE 更好 |
| 远距反射 | HZB 高效到达 | 64 步可能不够 | UE 更好 |
| 屏幕边缘过渡 | Vignette 平滑 | 硬切 albedo | UE 更好 |
| 时域稳定性 | TAA/TSR 稳定 | 单帧，可能闪烁 | UE 更好 |
| 天空盒处理 | History 含天空（可能渗透） | 排除天空（IBL 独立） | **我们更干净** |
| 合成公式 | premultiplied over | premultiplied over | 一致 |
| Specular Occlusion | `saturate((NoV+AO)²-1+AO)` | 同 | 一致 |
| Off-specular peak | `GetOffSpecularPeakReflectionDir` | 同（+normalize） | 一致 |

## 10. 改进路线图

按投入产出比排序：

| 优先级 | 改进项 | 预期收益 | 工作量 |
|--------|--------|---------|--------|
| P1 | 屏幕边缘 Vignette | 消除反射截断感，~5 行代码 | 极小 |
| P1 | 自适应步长（步长随距离递增） | 远距反射质量提升，无需 HZB | 小 |
| P2 | HZB 层次化行进 | 远距反射效率 + 质量大幅提升 | 中（需 HZB 生成 pass） |
| P2 | 多帧时域累积 + 邻域 clamp | 消除闪烁，提升粗糙反射质量 | 中 |
| P3 | 多射线 GGX 锥追踪 | 物理准确的粗糙度模糊 | 大 |
| P3 | 线段插值替代二分搜索 | 减少 5 次采样，微小质量损失 | 极小 |
